# 棉花糖小屋

在云海上的小岛建房、摆家具，邀请小动物入住。给 6–12 岁孩子设计的离线优先装扮游戏，代码绘制全部场景。可双击离线玩，也可从网站登录自己的账号，自动保存并跨设备继续。

源码仓库：[chengzicheng0927/czc-game](https://github.com/chengzicheng0927/czc-game)，主分支为 `main`。仓库保留游戏源码、测试、原型与项目文档；数据库、账号资料、个人存档和本机工具缓存由 `.gitignore` 排除。Git 中的源码不包含这些数据的备份，使用前请另行保管 JSON 存档与服务器数据库备份。版本管理步骤见[运行手册](docs/runbook/README.md#源码版本管理)。

## 邻居小屋与实时串门

串门有两种方式：**路过看看**（只读，主人不会知道你来过，页面会显示屋里现在有谁）和**敲门串门**（主人在主游戏页收到提醒，点「请进」后两人在屋里或前院互相看见、聊天；主人可随时请离）。主人在「邻居小屋 → 朋友敲门」里开关接待，默认关闭；第一次公开小屋时会问一次。新存档第一次进入时可以从8套人物预设里挑一个样子，登录后若账号尚未设置过个人形象，第一步也会自动弹出设置个人形象引导；同屋形象相同的小朋友会自动加上彩环和不同颜色的名牌。

网站版主场景远处漂着邻居的小云朵：每朵云托着一间公开小屋，在线优先、最多40朵，位置按小屋编号固定。有人串门的小屋会亮灯、出现小人影和称呼；点击云朵弹出小卡片，可「去串门聊天」（未满员时）或「去看看」，均在新页面打开。右下角「☁」按钮飞到云海全景；双击 index.html 离线运行时没有云也没有按钮。

网站版点击主界面的「邻居小屋」，先看「正在一起玩」的小屋，再看按最近公开更新时间排列的其他公开小屋；无需登录即可参观。在线区按小屋展示实际主动加入的公开称呼、人数与屋主是否在场，也保留自己家里的朋友；普通区排除本人并去重在线小屋。这不是登录账号名单。列表打开且页面可见时每10秒更新在线区；刷新失败会标明上次状态，并暂时收起直接加入动作。参观页与主游戏一样是软陶3D外观（没有WebGL时退回2D画法），可看整座、分层、指定房间和外观视角，拖动和缩放，点击「回自己的小屋」继续游玩；不会读取、替换或保存自己的进度，也不会占用自己的标签页写入租约。

每个孩子的小屋默认公开：登录并关联、云端保存后，系统自动生成脱敏公开快照，之后每次保存都会自动跟随最新布置；展示昵称取孩子自己填写的账号昵称，没填时用「小小建筑师」，绝不使用登录名。可在「邻居小屋 → 公开我的小屋」修改公开小屋名与展示昵称；「撤下公开模样」须确认，成功后列表和原链接均不能再获取，之后保存也不会再自动公开，随时可以重新公开；自己的小屋进度继续保留。

能打开网站的人都可能参观已公开的小屋。公开内容包括房屋与家具装修、前院、阁楼、当前形象、入住角色及实际挂出的像素画；账号名、生日、钱包、库存、心愿、领奖记录、相册、回忆与完整存档不公开。未登录仍可照顾本机小屋，离线文件版也继续可玩和导出JSON。公开范围见[公开小屋合同](docs/public-neighbors.md)。

实时串门、在线邻居与直接串门均已实现并部署；本轮66脚本758组串行检查、正式HTTPS在线摘要/称呼、双账号聊天及重启隔离验收通过。有空位的在线条目可点「去串门聊天」：已登录者在可见参观页自动加入一次，沿用当前已公开的串门称呼，其次自己的公开小屋昵称，最后「小小建筑师」，不会取登录名或账号昵称。游客仍只读，可从页面登录入口继续；满员或过期状态只提供普通参观。普通参观及主人「在我家一起玩」仍可主动填写昵称并点「加入串门」。每屋最多8人，最终容量由加入时的服务器判定；失败、退出或刷新不会自动重试加入。在线形象由服务器从本人已验证云档取得，无云档时使用默认形象。完整边界见[在线邻居合同](docs/online-neighbors.md)。

加入后可点地面、使用键盘或方向控件走动，看见同屋朋友的位置。选择房间只改变观察范围，先点进入按钮才把自己移到该房间，再点地面走动；前院也可进入。可发送1–80字纯文字或4条快捷短句，本次加入前的聊天不会补发。屏蔽只隐藏本次串门中的对方聊天，人物仍可见；主人可请离成员，被请离者在本次房间生命周期内不能重加。家具与房屋仍只读，走动、聊天不会写进私人进度或SQLite，不提供交易或共同布置。撤下公开模样会结束该屋联机；主人保存新布置时联机不会中断，访客画面会自动换成新布置、聊天和位置保留；离线、会话过期或服务重启后按页面提示主动重新加入。完整边界见[实时串门合同](docs/realtime.md)。

## 声音与朗读

「听一听」需要主动点击，再点一次停止；没有自动播报，也不需要先启用朗读开关。只读取指定的台词或说明正文，不会把菜单、按钮和图标一起念出来。朗读使用设备已安装的常规中文声线，自动选择优先普通话、自然或增强声线及 Tingting，过滤 Eddy、Grandma 等角色效果声线。设置中可更换声线并试听；若设备没有可用中文声线，会显示安装提示。

这是本机语音合成，没有真人录音，实际质感取决于设备与声线。配乐和点击音同样在本机生成；当前本地版本的背景音乐已换成原创轻快游戏风：白天《软糖跳跳街》（126 BPM），夜晚《月光蹦蹦桥》（108 BPM），短音主旋律配独立低音和反拍和弦，点击仍使用短木质触音。音量与静音设置保留；静音或切后台会停止朗读并淡出音效，关闭对话也会停止其朗读。此音乐改动按用户要求暂未更新线上，试听与验证见[记录](docs/verification.md)。

## 存档与回忆

游戏先在当前浏览器自动保存。网站版登录并明确关联小屋后，再自动上传到该账号的SQLite云存档；离线时继续本机游玩，联网后重试。**清除浏览器数据、换浏览器或移动离线目录前，先确认同步完成，并定期下载 JSON 备份。** 尚未同步的操作可能只在这台设备上。

- **JSON**：完整进度，包含版本信息、居民心愿与好友领奖、主线/剧情/成就/每日宝箱领取记录、七片彩虹、相册/回收夹小图与装饰、图鉴印记和套装领奖、四款小游戏记录、花园时间线与库存、落地家具深度、衣橱与搭配方案、外观拥有权、前院摆放、节日领奖记录、20幅像素画作/挂墙/墙纸引用、礼盒日期/累计/最近结果和设置，可在设置中重新导入。
- **Markdown**：从当前存档生成小屋概况、主线与已读章节、彩虹派对状态、已点亮成就、相片名字/配文/贴纸数、图鉴进度与套装徽章、好友等级、当日心愿与领取情况和事件回忆，以及画作名称/像素编码与礼盒记录，方便阅读，不作为可恢复的存档。
- 读档失败会尽可能保留损坏存档原文；存储不可用会在界面提示导出备份。
- 普通离线网页不会自动覆盖任意磁盘文件；导出通过浏览器下载，恢复通过本地文件选择。
- 「重新开始」需要两次确认，第二次持续按住 3 秒。
- 已关联账号时，导入JSON或重新开始后的进度也会同步到该账号；确认前界面会说明。空账号的首次新建是独立选择，不能用它绕过已有账号的重置保护。
- 旧版同版本存档会补齐新增小游戏记录和空花圃；已有种子库存不会重复发放。旧音频设置会迁移为较低音量并保留静音，重新自动选择常规中文声线。小游戏进行中的棋盘、倒计时和选牌状态只保留在当前页面，刷新后不会恢复本局。
- 旧落地家具缺少深度时补为 75%；旧衣橱补齐固定基础服饰，旧外观补齐默认拥有权，均不会反复发币。节日调试日期和未购买的外观试穿只在当前页面内保留。
- 旧17条任务的ID和既有奖励保留，已领凭据不会重发；新增任务按首个未领取项补进主线，不倒退旧章节。旧档没有累计烘焙记录时，只以已保存的最高订单和当日局数补可确认的下限，之后按真实蛋糕局数与订单继续累计。相册JSON保留小图和装饰，最近照片的大底图只在当前页面内存中。旧照片不被强制改写为新格式，回收夹也随JSON恢复。

恢复和排障步骤见 [运行手册](docs/runbook/README.md)。

## 网站账号、自动存档与离线缓存

2026-10-29已实现并部署零第三方依赖的Node网站与账号后端、SQLite完整JSON/修订/历史/会话、可选自动同步和网站离线缓存；主界面账号入口、邻居公开快照与只读参观也已上线。随后授权的实时串门与聊天也已实现并部署，使用独立内存房间。前端仍使用原生Canvas、普通脚本和本地素材；账号与服务器不是离线游戏的前提。JSON导入、账号切换和恢复先保证本机可保存，拒写时停止切换并保留原因与备份入口。

- **每个孩子独立。** 一个账号保存一座小屋；首次另一台设备登录后主动选择云端小屋。已经关联的设备在版本没有分叉时自动续接；两边都玩过时保留分支，明确选择继续本机或云端，不把金币、家具和领奖记录拼接。
- **本机也保留副本。** 切账号、退出和恢复前先保存原副本，配额不足就停止，不静默删除旧进度。「本机保留的副本」可下载JSON，整理非活动副本前须明确确认。另一个标签页正在保存时，这页只读，需主动选择「在此页继续」。
- **断网重新打开有前提。** 网站通过Service Worker准备公开入口及不可变资源；账号面板显示离线副本状态，等「已准备好」后才可依赖断网重开。浏览器清理缓存、隐私限制或准备失败仍可能影响它，JSON与原离线目录继续保留；账号API不缓存。
- **云存档包含完整持久进度。** 昵称、生日、相册小图和画作会随JSON上传到自己的账号；大底图、小游戏局内状态和临时预览不上传。不登录时可继续单机。密码仅用于注册/登录，不写入游戏JSON或localStorage；后端保存加盐哈希。
- **默认公开，可随时撤下。** 云存档保存后默认自动发布并跟随更新公开模样，撤下后不再自动公开；服务器只从本人已同步进度生成视觉白名单快照。灾难恢复轮换服务端epoch会撤销全部公开记录与旧链接，并连同“不公开”选择一起清除，之后每个账号下次保存会按默认公开重新发布新的公开小屋（此点已记入TODO待决）。

本地验证使用Node.js 24.3.0，内置`node:sqlite`在该版本会提示ExperimentalWarning，无需npm依赖。应用服务器的`marshmallow-cottage.service`以专用非root用户`mc-cottage`运行并启用开机启动，代码与持久数据分离；独立Node.js 24.22.2已核对官方SHA-256并实际验证SQLite和scrypt，系统Node.js 16保持不变。账号阶段19项上游HTTP与117资源检查保留为历史证据；此前只读参观更新已通过正式HTTPS正常证书校验和全部122份发布文件hash核对，匿名列表/详情/参观可用，Chrome已实际绘制正式站点的公开小屋。独立验收账号的私人修订/hash与公开快照经服务重启保留，撤下后公开404且私档不变。真实双物理设备、Safari、长期使用与异机灾备恢复仍待验收，实时共同布置未实现。详细用法见[运行手册](docs/runbook/README.md)、[部署与验收](docs/runbook/deployment.md)、[账号存档合同](docs/cloud-save.md)和[后端命令](server/README.md)，演进边界见[联网方案](docs/network-plan.md)。

准备发布副本可运行 `node server/cli.cjs prepare --data-dir .server-data --base-path / --activate`，它只生成本地文件，不监听端口。启动服务需明确host/port；同data-dir首次激活后固定挂载路径，不能在更新时随意改路径。更新部署按运行手册核对环境，不把示例端口当服务器约定。

## 技术与文件

原生 HTML + CSS + JavaScript，普通 script + IIFE，统一 window.Game 命名空间；Canvas 2D 绘制，DOM 面板操作，Pointer Events 支持鼠标与触屏。无第三方运行库、CDN、外部字体、图片或音频。

```text
index.html        游戏入口
css/style.css     界面与响应式样式
js/core/          状态、事件、存档、离线音频、可选账号同步、公开投影、实时串门与离线缓存
js/data/          数值、配乐、小游戏、作物、日历、服饰、庭院与外观
js/systems/       游戏规则、时间节日、换装、庭院与外观购买
js/render/        场景/2.5D投影与房间壳、天气、玩家、庭院、外观与在线人物绘制
js/ui/            可爱控件、各玩法面板与小游戏、账号入口、邻居、独立参观与聊天
js/main.js        启动编排
server/           可选Node/SQLite账号存档、公开快照与内存联机服务、白名单发布与版本切换
```

3D家园切换整屋／楼层／外观时，`js/render/world3d.js`的`build()`会复用“室外缓存”（主岛、前院、花园、邻居），只重建房屋部分；同一state下缓存命中的构建约11 ms，原约45–88 ms。缓存键含原型庭院可用性、隐藏家具、邻居与花园作物状态（阶段/成熟/缺水），`invalidate()`（存档、时间、形象变化等）会清空，单房摄影不走缓存。
