# Design System: 棉花糖小屋 · 云岛生活 3D 原型

## Overview

**Creative North Star: "掌心里的软陶云村"**

这是可转动、可走动的微缩云岛：奶油色小屋落在有厚度的草地与云团上，珊瑚屋顶、薄荷树冠、花盆和生活小物形成可近看的层次。界面像围着玩具摆放的奶油纸牌，保留圆润、马卡龙色、同色描边和少文字的游戏性格。用户已指定更立体、更丰富的 3D 方向；方向合同位于本目录 `index.html` 的首个 body 注释，种子为 `43863a1d`。

本文件只记录 `prototype/` 中已经建成的独立审核原型，不替换上一级正式游戏的设计合同。视觉依据为 `style.css`、`app.js`、`scene.js` 与 `review/` 截图；已对照家园、装饰、结算、手机组队和手机画室。22 个审核页面让现有功能保持可找到，并串起邻里造访、组队准备、采星搭桥、共同点灯、合作烘焙和结算合照。具体功能归属以本目录 [覆盖矩阵](coverage.md) 为准。

**Key Characteristics:**
- 具有实体厚度、圆角、方向光和接触阴影的自绘软陶场景。
- 中央世界优先，HUD、左侧快捷入口、右侧纸牌和底部游戏 dock 围绕场景布置。
- 墨绿中文、奶油纸面与低饱和草木、珊瑚、奶油黄组合；夜景保留纸牌的温暖。
- 原生系统中文字体、内联 SVG 与原生 WebGL；没有外部字体、图片、音频、CDN 或第三方运行库。
- 可点击的原型状态与正式游戏规则分清，示例数据和新增构想始终可识别。

## Colors

色彩来自柔软食物与小型木制玩具：奶油纸承载操作，草木绿维持阅读，粉、黄、紫只点亮物件与状态。上方 frontmatter 是本文件的规范值，UI 与 3D 材质保留各自已经使用的近色。

### Primary
- **玉叶绿**（`jade`）：链接和次级文字动作的强调色。
- **压印叶绿**（`button-top`、`button-bottom`、`button-hover`）：主按钮从上亮下深的双层绿到悬停实色，承载摆放、准备、保存和领取等主要动作。
- **云岛青绿**（`scene-teal`）：门扇、植物细节和模型轮廓中的深绿。

### Secondary
- **奶油黄纸**（`butter-surface`、`butter-ink`）：合照等次级按钮的面与字；**星糖黄**（`scene-butter`）用于灯、礼物和可收集物。
- **珊瑚软陶**（`scene-roof`）与**草莓粉**（`scene-pink`）：屋顶、腮红、花朵、软垫及温柔的社交提示。

### Tertiary
- **薄荷树冠**（`scene-mint`）、**雾紫**（`scene-lilac`）、**浅湖蓝**（`scene-blue`）：邻岛屋顶、衣服、家具与小物的可辨识变化，不取代主要操作色。

### Neutral
- **墨绿**（`ink`）与**苔色说明字**（`muted`）：纸牌上的主次阅读层级。
- **奶油纸**（`paper`）：HUD、主要操作面板和按钮文字；**软叶纸**（`soft-surface`、`soft-ink`）用于低强调操作。
- **云水蓝**（`sky`）：页面底色，场景内部另外以径向渐变形成暖中心与冷边缘。
- **草坪、土层、奶油墙和木色**（`scene-grass`、`scene-soil`、`scene-cream`、`scene-wood`）：形成岛屿从云团、土层、草地到房屋的实体分层。

**The 材质分色 Rule.** UI 纸面与模型奶油墙、按钮绿与树冠绿各有用途；不要为了统一色号抹掉物件和操作面的区别。

## Typography

**Display Font / Body Font / Label Font:** `PingFang SC` → `Hiragino Sans GB` → `Microsoft YaHei` → `sans-serif`。使用操作系统可用的中文字形，不加载外部字体。根元素字重为中等（500），并关闭合成字形（`font-synthesis: none`）；实际字重表现随系统字体可用级别变化。

**Character:** 中文无衬线清楚、厚实，标题带一点童话式停顿。场景标题多为一到两句短话，操作名用动词，详细说明留在侧面纸牌。

### Hierarchy
- **Display**：仅开场主标，使用 frontmatter 的 display 角色；中屏降为（40px），手机为（36px）。
- **Headline**：普通桌面场景标题使用 headline；超宽屏增至（37px），依次在（1150px）、（850px）、（600px）断点收为（26px）、（24px）、（22px）。画室桌面单独保持（26px）以避让画板；结算标题另用（33px），手机为（25px）。
- **Title**：纸牌标题使用 title；中屏为（16px），手机恢复（17px），让下方独立面板仍有明确开头。
- **Body**：侧面引导段落使用 body；场景副标题为（12px / 1.7），手机为（10px / 1.7）；任务名称通常（12px），补充说明（10px）。
- **Label**：dock 常规标签使用 label；操作按钮为（12px / 750 / 1.4）；审核说明、物品补充和概念提示使用（8–10px）。数值用较粗字重，部分糖果和爱心数字启用等宽数字（`tabular-nums`）。

**The 原生中文 Rule.** 不以网络字体或图中文字替换中文层级；新画面沿用现有系统栈与短句语气。小字号是本轮密集审核原型的现状，不能据此声称已经完成儿童阅读或无障碍字号验收。

## Layout

桌面采用“世界在中间，工具围在四周”的空间模型，非内容网站的纵向卡片流。顶部审核条高（52px），游戏区为剩余视口并设最小高度（660px）；当前根容器使用 `display: flow-root` 和 `overflow: clip`，避免手机面板上边距折叠及领取奖励后内部滚动偏移。HUD 位于游戏区顶部（22px），左右（30px）；场景从左（90px）、上（80px）起，占宽（`calc(100% - 360px)`）、高（`calc(100% - 155px)`）。左侧快捷入口形成一列，右侧操作纸牌宽（282px）、内边距（20px），独立纵向滚动；底部 dock 居中，距底（32px）。

面板以少量任务行、子标签和双列物品网格建立密度；组间常见（8–9px），任务行上下（12px），段间（16–18px）。现有各玩法通过顶部 22 页选择器与总览对照，主要游戏导航保持 8 个入口：我的小屋、建造装饰、去串门、一起玩、游乐场、花园、杂货铺、回忆。居民、换装、成长、相册、活动另有左侧快捷入口；子标签承接低频细项，避免把全部功能同时压在场景上。

响应式行为来自以下实际断点：
- **超宽（≥1550px）**：操作纸牌宽（310px），内边距（24px），标题与 dock 略放大，场景为右侧内容预留更多空间。
- **收紧桌面（≤1150px）**：纸牌宽（260px）；隐藏顶部星碎片和账号文字，收紧 HUD 与 dock 间距。
- **中屏（≤850px）**：审核条（48px），游戏区最小高度（760px），纸牌宽（235px）并下移，场景与标题继续缩小；等级胶囊隐藏。
- **手机（≤600px）**：审核条（44px），游戏区改为自然高度并允许页面外层滚动，底部预留（98px）。场景仍绝对定位在上方，高（340px）、上限（43vh）；纸牌移入文档流，常规上边距（462px），两侧（16px），内边距（18px）。dock 固定在视口底部（13px）、左右（10px）；保留8个图标与文字入口。快捷按钮缩为（33px），镜头按钮缩为（29px），隐藏独立缩小按钮但保留放大、旋转和复位。物品网格改三列。
- **极窄（≤359px）**：进一步收紧品牌和 HUD，物品网格改双列、调色盘八列。

创作、游戏、相册与结算按各自主工具避让：手机画室面板上边距（520px）、画板宽（240px）；游乐场面板（557px）；相册（485px）；结算（475px）。这些是已实现的页面特例，不是可套用到所有新页面的固定模板。手机场景、画板与下方操作面板必须同时保留；滚动时固定 dock 维持导航。已有截图包括（1280×720）与（390×844）审核结果，不等同于所有设备验证。

**The 世界留白 Rule.** 新控件先进入既有 HUD、纸牌、子标签或工具条；让房屋、人物和地面有连续可看、可操作的面积。

## Elevation & Depth

场景是真实几何的正交 WebGL 微缩模型，DOM 控件另以边框、内高光、短硬底边和低透明柔影表达软陶纸牌的厚度。不是只有一个平面背景：岛屿有草坪、圆润土层和云团底座，房屋有屋顶瓦线、门框、窗台、花盆、烟囱和侧墙，室内以剖面墙、木地板、地毯、软垫与家具错位建立前后关系。模型使用球体、圆角盒体、圆柱与屋顶几何，方向光、半球光和轻微高光统一；地面接触阴影为低矮几何，不是实时阴影贴图。

### Shadow Vocabulary
- **环境轻托**（`0 10px 30px #426d6520`）：场景标签、活动提示等浮动内容的通用轻影。
- **纸牌厚边**（`0 9px 0 -4px #adbca36b, 0 16px 35px #4873651c`）：桌面侧面板，用短底边和柔影区分操作纸牌与云海。
- **按钮压印**（`inset 0 2px #ffffff35, 0 4px 0 -1px #2c624f, 0 7px 10px #3f6b5b20`）：主按钮的上缘亮边、下缘厚度及轻托影。
- **dock 底座**（`0 6px 0 -1px #95af9d75, 0 15px 22px #3a6c6220`）：承托整条导航，而非逐项悬浮卡片。
- **画板木框**（`0 9px 0 #977d5740, 0 18px 40px #5d68532b`）：画室的实体边框与略微旋转的手作感。
- **审核弹窗**（`0 30px 100px #244b4a40`）：比普通纸牌更强的遮罩层级，背后仅弹窗遮罩使用（6px）模糊。

夜景同时变更天空径向渐变、模型着色与场景标题；纸面仍保持浅色。结算标题使用奶油亮字（`#fff4d9`），说明为（`#f3ead6`），避免深色文字落在夜空上。白天、夜晚与天气预览是氛围切换；部分天气仅改变背景色，不代表完整粒子天气系统。

**The 轻量实体 Rule.** 保留可感知的实体体积，同时沿用原生、无贴图实现：静态几何合并一个顶点缓冲，当前每次渲染为单批三角形绘制；DPR 上限（1.5），请求低功耗 WebGL。更新循环最多约（30fps），仅 dirty 状态重绘，页面后台暂停，恢复时再标脏。操作导致的几何重建仍可能有成本，未做真机性能验收，不把低资源策略写成性能保证。

## Shapes

圆润外轮廓和小范围直线细节同时存在：纸牌与 dock 大圆角，操作按钮中圆角，物品小卡略方正，进度与货币用胶囊，头像和镜头按钮用圆形。frontmatter 的半径按实际使用部位命名，没有强行套入单一倍数比例。面板常配奶白（2–3px）边框；物品选中边为（2px）草木描边，并通过减少内边距保持原尺寸。

主图标为内联 SVG，通常（24px），线宽（1.8），圆头圆连接；dock 图标（28px），线宽（1.7）。模型保持圆角、短腿、厚屋顶、球状树冠和小体积生活物件。像素画板是有意保留的方格例外：内部（16×16）方格、外部木框，不能把像素格也圆角化。

## Components

### Buttons

按钮像可以轻轻按下的压印块。主要、奶油次级和软纸按钮共用圆角与内边距，最小高度（43px），图标间距（7px），字重（750）。主要按钮用上下渐变与底边阴影，次级按钮用奶油黄，低强调动作用软叶纸；文字动作带下划线。渐变、阴影和最小高度在 sidecar 记录，frontmatter 不把它们伪装成单色或固定高度。

全局悬停为轻微增亮（`brightness(1.025)`），按下位移（2px），变换、背景和阴影过渡（0.18s）；主按钮悬停另变为 button-hover。禁用态透明度（0.5）并使用不可操作光标。键盘焦点为（3px）深青轮廓、偏移（4px）。手机部分工具小于主按钮，这是当前原型事实，后续不能据此宣称全部操作满足大触点规范。

### Chips / Tabs / Swatches

小标签是低饱和纸片，默认（10px）、内边距（4px 7px）；在线态增加绿点，新增构想以暖纸底区分。子标签常规最小高度（30px），选中后变成白字草木绿，并设 `aria-pressed`。颜色圆点为（27px）并有奶白边，选中态增加外环与勾，不只靠颜色传递选中。

### Cards / Containers

操作纸牌采用 panel 半径、奶油纸底、奶白粗边与双层托影；只让纸牌内部在桌面滚动。任务行使用小圆角图标底、名称、补充说明、独立圆形前往按钮，分隔线轻而稀。物品卡居中摆放自绘 SVG 家具图，默认双列；选中后背景与描边同步变化。家具以代表性样本陈列，不能把写有目录数量的卡片视为全部资产已绘制。

### Inputs / Fields

搜索框使用薄草木边（1px）、浅奶油底、圆角（11px），内边距（10px 12px），字（11px）；聊天和设置输入框圆角（10px），仍共享清晰的焦点轮廓。聊天显示本地消息气泡，正文允许长词换行，输入上限（80字）；相册配文上限（30字）。审核笔记使用可调整高度的多行字段并可导出 JSON。未实现通用服务端表单校验与错误设计系统。

### Navigation / Review Shell

底部 dock 用单个厚实底座承托 8 个主要入口，当前项用浅绿凹面与下方短条双重标记。左侧快捷钮为圆角小块，桌面悬停或焦点出现文字，手机保留可访问名称并隐藏浮出文字。顶部审核条、前后页、22 页选择器、全部页面总览和审核笔记属于原型审核外壳，不应直接复制进正式游戏体验。弹窗用原生 `dialog`、可见关闭按钮和柔暗背景；提示使用 `role=status`、`aria-live=polite`，不夺走场景主操作。

### 可转动的云岛与场景热点

拖动越过（6px）阈值后旋转方位与仰角；仰角范围（0.24–0.95弧度）。滚轮及镜头按钮改变正交缩放，范围（6–20）；另有旋转和恢复全景按钮。家园、串门、组队和协作场景支持点击岛内地面移动，方向键 / WASD 提供等价移动，输入框、画板与弹窗操作期间不拦截方向键。移动保持岛内边界，家园与串门另避开房屋主体；人物瞬移到目标并出现落点圈，当前没有真实路径寻路、骨骼行走动画或多人位置同步。

场景标签、门铃、邻岛名片和金色星糖是 DOM 热点，叠在模型上方。它们在当前视图中按页面布局定位，不是跟随任意旋转角度的 3D 物体投影拾取；新页面不得把这种定位方式描述成通用空间 UI 引擎。WebGL 不可用时有简化 Canvas 房屋回退，不保证回退画面完整复制全部 22 屏三维场景。

### 已实现原型与待实现概念

本轮已实现的是 22 屏导航、场景绘制、按钮与面板、示例聊天、敲门/请进状态、准备状态、采集→搭桥→点灯→结算、原型内奖励防重、合作烘焙步骤、画板和相册等可审核交互。正式游戏的所有现有功能入口以代表性样本覆盖，未重写全部正式规则或（407件）家具。

敲门征得屋主同意、匿名路过、人物预设与接待控制属于已经确认的待实现设计；云朵广场、2–4人组队、协作采星搭桥点灯、合作烘焙、团队奖励与纪念合照是新增概念。邻居、聊天、账号、在线状态、队友、库存与奖励均为演示；没有连接账号、公开小屋或实时 API，不读写正式游戏存档。审核笔记、照片、画作和进度只在当前页面内存，刷新清空；相册 PNG 当前输出场景底图，完整贴纸装饰导出仍以正式游戏为准。深度、头像细分、部分天气等控件主要演示状态和流程，不能当作完整功能验收。

系统的 `prefers-reduced-motion` 会关闭 CSS 动画与过渡；原型内“减少动态”开关目前改变滚动行为与示例状态。场景本身采用按需重绘，没有持续环境动画，因此不把该开关描述成已实现全量动画调度。声音默认关闭，轻音由主动操作触发，不加载音频文件。

## Do's and Don'ts

### Do:
- **Do** 保留中央可转动的实体云岛、圆角微缩物件和奶油纸操作层，扩充生活细节时仍让主场景可读。
- **Do** 沿用原生中文系统字体、自绘 WebGL / SVG 和现有色彩分工。
- **Do** 让全部现有玩法保持可找到，并用标签、说明和流程反馈清楚区分现有、待实现与新增构想。
- **Do** 同时检查桌面纸牌滚动和手机页面滚动，保证场景、主工具、固定 dock 都能找到。
- **Do** 保留焦点轮廓、文字标签、选中勾与禁用反馈；场景操作维持镜头按钮和键盘等价入口。
- **Do** 延续单批几何、按需绘制、后台暂停和 DPR 上限等已经采用的低资源策略。

### Don't:
- **Don't** 修改或把本原型文档当作上一级正式游戏设计的替代品。
- **Don't** 引入外部字体、图片、音频、CDN 或第三方前端运行库来重造当前世界。
- **Don't** 把示例账号、聊天、在线人数、队友、库存或奖励描述成真实联网与持久进度。
- **Don't** 把入口覆盖、代表性物件、天气氛围和状态提示说成全部正式规则、全部资产或完整服务端能力。
- **Don't** 用密集 HUD 或新的常驻卡片挤掉房屋、人物与地面的连续可看区域。
- **Don't** 把桌面和手机截图审核提升为真机触控、完整无障碍、跨设备或性能验收结论。
