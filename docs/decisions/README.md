# 架构决策

## ADR-001 离线原生页面与本地存档

状态：采用。日期：2026-10-27。

背景：用户要求能在本地玩游戏，并允许用 Markdown 或其它文件保存游戏记忆。需求文档指定双击 HTML 运行、无外部依赖。

决定：Canvas 2D 负责绘制，DOM 负责操作；普通脚本以 IIFE 组织并使用 window.Game。所有持久状态通过 store.update 修改。localStorage 自动保存，JSON 是完整存档的权威格式，Markdown 是由状态生成的可读回忆录。JSON 导入先校验结构与版本，再替换内存状态并保存，保留损坏存档备份。

备选：以 Markdown 保存所有状态会增加解析复杂度；后端数据库和桌面封装会增加安装或联网要求。当前均不采用。

后果：无需服务器或安装依赖，但浏览器存储与页面地址相关，文件移动、浏览器数据清除后应通过 JSON 备份恢复。未授权的浏览器页面不能自动覆盖任意本地文件。


## ADR-002 保留手绘人物的 Canvas 2.5D

状态：采用。日期：2026-10-27。

背景：用户认为平面房间不便摆放，希望评估3D或2.5D，并要求不要启动多个预览服务增加机器负担。

决定：继续使用Canvas 2D；房间壳独立为room-shell，坐标投影独立为room-space，家具和人物保持手绘平面形象。地面家具使用0—1深度和近大远小投影，人物与家具按深度绘制，拖动、命中与落点共用投影和反变换；台面小物继承父家具深度。旧存档地面家具补75%深度，原x/y保持兼容。

资源：只复用4174一个本机预览服务和已有浏览器页，规则检查串行运行。场景绘制上限30帧，低动态12帧，小游戏背景5帧，隐藏页面停绘；画布DPR上限2，静态房间壳缓存最多12份。

后果：已有角色和家具可继续使用，并能按前后位置摆放；不提供自由旋转镜头或真实3D模型。完整3D暂缓，避免增加引擎、模型与机器负担。帧率上限是实现约束，没有把它视为设备性能基准。

## ADR-003 可选网站后端与离线进度边界

状态：采用首期本地实现，未远端部署。日期：2026-10-29。

背景：用户希望游戏通过网址访问，明确首期各浏览器保存自己的进度，先规划实现前后端再考虑部署；后续可增加后端业务并用本地SQLite。

决定：保留原生IIFE/Canvas及离线入口，新增Node.js标准库网站服务；从入口资源白名单生成不可变release，显式激活/回滚、固定路径前缀，并提供健康/版本接口。只修改发布副本的资源路径，不把后端或构建变成离线运行前提。首期无服务端业务数据，不创建空库；后续数据库采用SQLite，账号/云档/互访仍按独立阶段实施。

进度仍由本机localStorage与JSON恢复，导入/reset先真正保存再切档。网站托管不自动同步进度，不将朋友档导入个人store作为互访。未来APISIX入口代理到应用服务器，部署时再核对实际环境。

后果：首期无需第三方运行库或数据库守护进程，可保持旧JSON和离线体验；同时承担Node服务、release留存及网关缓存配置的运维。当前不承诺跨设备同步、多人共同布置或网址版冷启动断网可玩。细节见[分阶段方案](../network-plan.md)和[运行命令](../../server/README.md)。

补充：以上记录A首期决定；同日用户追加账号／SQLite与离线缓存要求，当前边界由ADR-004扩展，不将A的历史限制当成现阶段能力。

## ADR-004 可选孩子账号、SQLite整档同步与离线副本

状态：采用并本地实现，未部署。日期：2026-10-29。

背景：用户要求每个孩子区分进度、跨设备继续玩，同时保留离线缓存和JSON备份，先本地测试。原游戏只有浏览器localStorage，直接上传会遇到首次登录覆盖、离线分叉、旧页写入和账号切换风险。

决定：沿用单实例Node服务，使用本机实测Node.js 24.3.0内置SQLite；每个账号一份完整JSON、修订和历史，用户名／密码不要求真实身份。密码加盐scrypt，会话用HttpOnly/SameSite Cookie，认证写校验Origin／CSRF／归属。前端可选同步adapter监听真正本机保存成功的快照，以ETag CAS和幂等回执提交；只一边变化时续接，两边变化保留分支并让用户选择。build与数据合同兼容门禁、epoch及本机generation拦截旧页／恢复／账号切换的迟到响应。

guest与账号本机副本分开保留，写入租约从store和save拦截旧标签，拒写／配额不足时不切档。本机仍先保存，SQLite为账号持久进度，JSON为可导入备份格式，MD只作阅读；不把密码或会话写进游戏JSON。Service Worker只缓存固定release的公开页面壳和资源，不缓存API或账号数据；旧页面关闭后再更新。file入口仍无网络依赖。

备选：没有采用每家具数据库行、逐字段经济合并、WebSocket、Redis、外部数据库或家庭配对码，这些都不改善本轮个人整档续玩目标。未引入前端框架或npm SQLite驱动。

后果：用户可不登录单机，也可登录跨设备续玩；离线修改可能形成分叉，不能保证自动合并两个设备的全部收获。SQLite当前版本有ExperimentalWarning；自动7份备份仍在同盘，实际部署需外部灾备。无密码找回或管理后台，浏览器可能清理本机缓存，仍应保管账号和JSON。朋友参观／协作不在本轮。详见[账号存档说明](../cloud-save.md)与[验证记录](../verification.md)。
