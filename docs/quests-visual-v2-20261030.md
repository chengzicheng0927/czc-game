## 交付行为

主线沿用成长绘本、奶油纸、可可正文、章节书脊和七色进度。五章书脊可浏览，未来章节明确锁定；本章当前未领任务在前，其余清单折叠，展开状态在切签与领奖重绘后保留。章节数、标题、描述、已领进度均读取`sys.quests.chapters()`；真实35任务8/6/7/7/7不复制为另一套UI规则。

任务同时呈现进行中、尚未开启/日期锁定、可以领取、已领取。复合任务整体显示满足的条件数，各条件保留真实名称与progress/target；满足条件但仍locked的后续任务不开放领取。奖励继续读取真实reward，七色来源与既有奖励/ID未改。任务行动将`q.action`原对象完整交给`api.navigate`，不丢居民、房型、家具、墙纸、主题、小游戏、合奏等字段；保留无action时的既有导航回退。

每日展示真实存档日期与三张任务卡，来自四项日期轮换：摆家具3件、小游戏2局、摸头3次、收获3份，各40糖果+15经验。任务动作完成与领取奖励分开，宝箱按`dailyChest().done`的已领取份数显示，三项收好后再手动开启一次，奖励80糖果+30经验+5爱心。UI不改日期、不补领，不把未来日期已达标任务算进可领奖页签数量。每日列表使用`ol/li`语义。

成就用真实八类metadata和派生categories/list/summary展示五阶共40枚，包含进行中、前阶待领、可以领取和已领取。奖励名称来自真实家具/服饰目录；八顶阶家具保留`canvas[data-furniture]`，由公共既有缩略图流程绘制。`baker_3`的`dress_daisy`真名、同款不重复/换币说明与领取后精确衣橱入口保留。两里程碑只读，说明随主线自动收好，显示实际纪念家具与奖励，没有新增领取按钮。

派对入口只读取`ending().unlocked`，保留35主线与七色门槛；重播调用原party API。领取结果仍优先处理`endingUnlocked`，其次处理`chapterCompleted`，继续打开原派对或章末故事。story/portrait/party函数保持，故事仍只在主动点击时朗读当前句，翻句停止，不自动朗读整页或重做剧情。

三页签使用tablist/tab/tabpanel关联和单一Tab入口，支持左右/Home/End切换。页签、章节、类别和操作使用稳定`data-ui-focus`与公共重绘机制协作；领奖焦点回到可阅读的当前任务、每日卡/宝箱或具体成就，避免停留在已禁用的领奖按钮。窄屏章节切换后，焦点书脊执行block/inline nearest就近滚动，避免重绘横向列表后选中章节留在可视区外。`focus({tab:'achievements',category?,milestoneId?})`保持，里程碑会展开、定位到具体条目并聚焦。

焦点恢复保留意图直到最新连接成长册完成定位；二层RAF跨过公共面板首次打开的标题聚焦与规则触发的排队刷新。故事等模态存在时暂停，模态关闭后再恢复。关闭、重建与换档的旧按钮、选择回调和迟到焦点均失效，换档清空类别/章节/来源/折叠/反馈。

领取只调用`sys.quests.claim/claimDailyChest`或`sys.achievements.claim`，UI不直接写store/钱包/凭据。规则正常返回后才转交`api.doAction`；抛出或无有效结果按失败处理、留页并重读权威状态，不给成功动画或打开故事/派对。测试还覆盖规则已提交后总线抛错：仍报未能确认并重读实际已领状态，不伪造回滚或成功。写入仍是现有普通`store.update`，没有新增`persist:true`、同步落盘或持久原子保证。读取失败有重读入口，主线/每日/类别无内容时有明确空态，缺失服饰元数据安全降级。

新增CSS只约束成长册：桌面书脊与章节并排；860px以下任务奖励/操作排到正文后；620px以下内容单列、书脊局部横向可滚、复合条件单列、奖励和48px按钮完整换行。没有新增固定内容高度、隐藏溢出来压缩任务，沿用既有抽屉内部滚动。以上是源码布局意图与静态审计结果，未冒充浏览器实际几何验收。
