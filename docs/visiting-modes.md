# 串门升级与形象多样化：需求、设计与工作拆分（已在本地实现并验证，未部署生产）

2026-10-29用户提出两项新需求，要点确认后按本文一次实现；实现记录见第8节。

## 0. 现状（已核对代码）

- 串门：登录用户打开`#join`或点「去串门聊天」即**直接加入**，屋主**不会被通知**，也无需同意（`js/core/live.js`、`server/live-hub.cjs`）。游客只能读屋主**主动发布**的公开快照，不能走动/聊天。
- 屋主"在场"：只有屋主自己打开参观页并加入时`hostOnline`才为真；**主游戏页不渲染别人**，`live-avatars.js`只接在参观页。
- 形象：联机会发送完整形象（服务器从本人已验证存档取白名单字段，`live-hub.cjs:93`），所以改过装的人互相不同。但**新账号默认形象固定**（双马尾+粉裙+红蝴蝶结，`outfits.js:93`，无随机），刚进来的小朋友看起来全一样。
- 传输/容量：长轮询≤8秒，每屋≤8人，35秒无心跳过期，位置/聊天只在内存，不入SQLite。聊天1–80字，限速，可本地静音，屋主可请离。

## 1. 需求A：形象多样化

| 编号 | 需求 | 验收 |
|---|---|---|
| A1 | 提供一批**预设角色**（建议8套：发型、发色、肤色、表情、起始服装各不相同）。新存档首次进入时从中挑一个，默认随机预选，可再微调。已有存档不被改动，仍可在换装间自由更换。 | 随机生成100个新存档，8套预设都出现；任意两个新账号相同形象概率≤1/8；旧存档形象逐字节不变。 |
| A2 | **同屋防撞脸**：同一间屋里若两人形象指纹相同，其中一人自动加区分标记（名牌色环/小帽色），由peerId稳定决定，双方看到一致。 | 两个相同形象同屋，名牌/标记可区分；一方退出再进，标记不乱跳。 |
| A3 | 名牌颜色按peerId从固定调色板分配，保证任意两人名牌可区分（不依赖形象）。 | 8人同屋名牌两两不同色。 |

不涉及服务器新数据：预设仅是客户端创建选项，联机仍走既有形象白名单。

## 2. 需求B：两种串门方式

### B1 敲门串门（需屋主同意，双方同屋可见、可聊天）

1. 访客在邻居列表/云海卡片点「敲门」。服务器建一条**待处理请求**（仅内存）：访客公开称呼+形象，有效期2分钟；同一访客同一屋同时只有一条；一屋最多同时3条待处理。
2. 屋主在**主游戏页**收到轻提示卡：头像+称呼+【请进】【婉拒】【稍后】（静音时无声）。屋主不在线 → 访客看到"主人现在不在家"，v1不排队。
3. 请进：服务器发一次性入场凭证（绑定屋、账号，5分钟有效）；访客据此加入；屋主的主游戏页同时接入同一实时房间。婉拒：访客只看到"主人现在不方便"（不区分拒绝与忽略），同一访客对同一屋冷却10分钟。
4. 会合后：两人可在**屋内某房间或前院/花园**走动，互相看见，文字聊天（沿用80字、限速、本地静音）。屋主可随时请离；任一方离开、掉线35秒或屋主关页面，会话结束。
5. 屋主设置「接待」：开放敲门 / 暂不接待（勿扰，一键切换）。**默认暂不接待**，首次公开小屋时询问。

### B2 匿名路过（屋主不知情）

- 任何人（含已登录）点「路过看看」：只读公开快照，**不创建实时会话、不发心跳、不计数、不弹提示**；屋主任何界面都看不到。
- 界面明确写"路过模式：主人不会知道你来过"，不能聊天/走动、不显示自己的形象。
- 页面内有「敲门」入口，一键转为B1（此时才会通知屋主）。
- 应用层不记录路过者；服务器访问日志按运维既有配置，不用于向屋主展示。

### B3 屋主当前模样（待确认的关键设计）

现状访客只看到**发布时的快照**，与屋主当下的房间可能不同，"一起在房间里"会割裂。建议：屋主点【请进】即授权**本次会话**发送其当前外观快照（不改变公开快照），会话中屋主布置变化每30秒或每次变化后增量同步；会话结束即丢弃。

## 3. 服务端草案（全部在内存hub，不入SQLite）

- `POST /live/knock {houseId}` → `{requestId}`；`GET /live/knock/status` → `pending|approved(+ticket)|declined|expired|host_away`
- `GET /live/inbox`（屋主，长轮询，仅「接待开放」时）→ 待处理请求列表；`POST /live/knock/answer {requestId, accept}`
- `POST /join`：非屋主必须带有效入场凭证；**取消`#join`直达和「去串门聊天」直接加入**，入口改为「敲门」与「路过看看」。
- 速率限制：每账号每分钟敲门≤3次；每屋待处理≤3。

## 4. 对现有功能的影响

邻居列表、云海卡片按钮、在线邻居`#join`快捷入口、`docs/online-neighbors.md`的"直接加入"条款、AGENTS.md授权描述都要同步修改；测试`live-api`、`visit`、`neighbors-ui`、`online-neighbors-api`、`sea-map`需改写或新增。

## 5. 隐私与儿童安全

不暴露账号ID/用户名/peerId；称呼用公开称呼；敲门无自由文本；待处理请求与会话仅内存；婉拒不透露原因；屋主可随时请离；聊天沿用既有限制；路过模式不产生任何屋主可见痕迹；file入口不联网。**持久屏蔽名单需要新增SQLite表，须另行授权**，v1只做会话内请离。

## 7. 已确认（2026-10-29用户回答）

1. 形象：做**更多人物预设**（约8套），本期不加动物等物种；物种另行分期。
2. 会合地点：访客进入**屋主此刻所在的房间/前院**，走出房间即前院。
3. 路过模式：**显示在线人数和称呼**，沿用既有匿名接口`/neighbors/online`（只有人数、称呼、屋主是否在场），不显示位置、形象和聊天，也不建立会话。
4. 屋主不在线：只提示"主人不在家"，v1不做留言、预约或排队。
5. v1不做持久屏蔽名单，只做会话内请离（持久屏蔽需新增SQLite表，须另行授权）。

B2中"路过模式不显示屋内有谁"改为：只显示上述公开的在线人数和称呼摘要。

## 8. 实现记录（2026-10-30，仅本地与127.0.0.1:4173预览）

已完成：
- **形象**：`js/data/outfits.js`8套预设（只用初始衣橱5件物品，不送额外衣物）；新存档首次进入先挑形象（随机预选，关闭弹窗也按预选应用），衣橱里「挑一个预设形象」随时可换；老存档（引导已完成/已开始/外观已改）不会被打扰。联机`live-avatars`与主游戏页`live-peers`同屋防撞脸：相同形象加同色彩环，名牌色按排序后的peerId分配8色，各端一致。
- **敲门**：`server/live-hub.cjs`内存协议（`knock`、`knockStatus`、`inbox`、`answer`，`/join`对非屋主强制校验凭证）；`cloud-api.cjs`新增`POST /live/knock`、`POST /live/knock/answer`、`GET /live/knock/status`、`GET /live/inbox`。客户端`live.js`的`knock/cancelKnock/reception`；`js/ui/live-room.js`在“需要敲门”时自动改走敲门流程（等待/取消/同意后带凭证加入）；`js/ui/reception.js`屋主接待开关与提醒卡（默认关闭，偏好在本机`localStorage`的`mc_reception`，首次公开小屋询问一次）。
- **路过**：不建会话、不发心跳；参观页新增匿名在线摘要（沿用`/neighbors/online`，只有人数与称呼）；入口文案改为「路过看看」「敲门串门」。
- **屋主同屋**：`js/ui/host-room.js` + `js/render/live-peers.js`，屋主点“请进”后用自己的公开小屋加入，主场景画出同屋的人，方向按钮/点地面走动，面板含聊天与请离；只读，不写存档。
- **人物头顶发言气泡**：`js/render/live-avatars.js`、`js/render/live-peers.js`、`js/ui/live-room.js`、`js/ui/visit.js`、`js/ui/host-room.js`同步支持同屋成员头顶对话气泡（最多2行自动折行与省略截断、6秒自动消散、走动不重置计时、本机「屏蔽聊天」立即隐藏对应成员头顶气泡，兼容参观页、主游戏页2D及3D标签层）。

与草案的偏差（如实记录）：
1. 入场凭证绑定“小屋+账号”，**5分钟内同一账号可重连**，不是严格一次性（刷新页面不必重敲）；被请离会立即作废并冷却10分钟。
2. B3“屋主当前模样快照”不另做会话内快照：2026-10-30起，主人保存云端后公开快照默认自动跟随最新布置，在线房间不再因更新而结束，访客页收到新版本号后自动重新读取（见realtime.md），因此访客看到的是主人最近一次云同步后的布置，而不是实时每一次拖动。
3. 屋主离线/关闭接待、请求2分钟无人回应、婉拒，访客分别只看到“不在家”“没回应”“不方便”。
4. 屋主的位置：同意后进入时站在正在看的房间，没有选中房间则在前院。

未验证：真实双设备/触屏、Safari、屋主页面后台时的提醒、长时间运行、生产部署；屋主页面的接待与同屋界面只有隔离测试（轻DOM）和代码审阅，没有真实双账号浏览器目视。

## 9. 主场景串门（2026-10-30，仅本地实现，未部署）

第8节的入口原本都是`<a target=_blank>`打开独立`/visit/<id>`页。现改为：无修饰键的左键点击且主场景串门可用（有`G.render.visit`、同源公开读取、非file入口）时，直接在主场景切换到对方的房子；其余（修饰键、中键、不可用）仍打开旧页，`js/ui/visit.js`保持不动。

- **路过看看（B2）**：只读公开快照，不建会话、不发心跳、不挂串门浮层；顶部横幅写“正在XX的小屋 · 路过 / 路过：主人不会知道你来过”，并保留“敲门串门”按钮转入敲门。未登录用户即使点“敲门串门”也先降级为路过，并引导登录。
- **敲门串门（B1）**：登录用户先读到快照，再挂载`G.ui.liveRoom`浮层走敲门；**等待期间仍在自己家**（场景不动）。屋主同意并连上才切场景；婉拒、不在家、没回应、取消、加入失败都留在自己家并提示。被请离、掉线重连失败、屋主撤下公开（404）则优雅回到自己的小屋。
- **自己房子**：“接待朋友，一起玩”走`G.hostRoom.enter()`（屋主同屋），不经公开快照。同一账号不同时在两个房子：进入串门前先结束屋主接待，屋主进入自己家前先结束串门（含取消敲门）。
- **装扮类面板**：串门中`ui.open`拦截build/decor/yard/exterior/houseDesign/roomLayout/shop/garden/residents/crafting/play/quests/collection/observatory，提示“正在串门，先回自己的小屋再装扮吧”；neighbors、账号、登录、换装、设置、回忆、帮助放行。
- 设计、接口契约与未验项：[main-scene-visit.md](main-scene-visit.md)。
